# Project Documentation

Welcome to the documentation repository for the project. This folder is dedicated exclusively to:
1. **System & Feature Documentation**: Architecture, API designs, specifications, and project overview.
2. **Team Member Change Logs**: Records of changes made by different team members, including context, PR references, and dates.
3. **Execution Guides**: Detailed step-by-step procedures on how changes are deployed, run, and verified locally or in production.

---

## Directory Index

- [PROJECT_OVERVIEW.md](./PROJECT_OVERVIEW.md): Problem, solution, users, features, stack, user flow and the three-phase roadmap.
- [BACKEND_ARCHITECTURE.md](./BACKEND_ARCHITECTURE.md): Backend modules, processing flow, FairRate formula, data model, errors and security boundary.
- [API.md](./API.md): Every implemented endpoint with request/response schemas, status codes and examples.
- [IMPLEMENTATION_PROGRESS.md](./IMPLEMENTATION_PROGRESS.md): Phase assessments, completed work, test results, known limitations and next steps.
- [CHANGELOG.md](./CHANGELOG.md): Contains the log of updates contributed by each team member and their impacts.
- [EXECUTION_GUIDE.md](./EXECUTION_GUIDE.md): Instructions on how to run, execute, and test code changes across frontend and backend, including environment variables.

---

## Documentation Policy for Contributors
Whenever you make changes to the codebase:
1. **Document your changes** in [CHANGELOG.md](./CHANGELOG.md) under your name with the date and PR/commit link.
2. **Update execution instructions** in [EXECUTION_GUIDE.md](./EXECUTION_GUIDE.md) if your changes require new setup steps, environment variables, or execution commands.
3. **Update** [API.md](./API.md) and [IMPLEMENTATION_PROGRESS.md](./IMPLEMENTATION_PROGRESS.md) when endpoints or phase status change.
4. Keep documentation clean, concise, and up to date.
