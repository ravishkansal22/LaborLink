How to work on LaborLink

Set up the project, run the backend and frontend, and send your changes through a feature branch and a pull request. Nobody pushes directly to main. Ravish reviews and merges every PR.

Ground rules

1

Never commit to main

main is the stable, demo-ready branch. All work happens on your own feature branch.

2

One feature, one branch, one PR

Keep PRs small and focused, so they’re easy to review and to undo.

3

Ravish merges

Open a pull request into main and request a review from Ravish. Don’t merge your own PR.

4

Green checks + docs

Tests, lint and typecheck must pass, and every change gets an entry in docs/CHANGELOG.md.

5

No secrets, no data

Never commit .env, API keys, backend/var/ (the database and uploads), node_modules/ or .venv/.

6

Keep demo honesty

Payments stay labelled “simulated” or “demo”. Don’t add fake login, real payments or identity checks without a team decision.

One-time setup

You need Git, Python 3.10+ and Node.js 18.17+ (20 LTS recommended). Check them with git --version, python --version and node --version.

1. Clone the repository

git clone https://github.com/ravishkansal22/LaborLink.git
cd LaborLink

2. Create the Python virtual environment (in the repo root)

Windows (PowerShell)

python -m venv .venv
.venv\Scripts\Activate.ps1

macOS / Linux

python3 -m venv .venv
source .venv/bin/activate

If PowerShell says scripts are disabled, run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once.

3. Install the backend dependencies

cd backend
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

Optional: copy the example settings. The defaults work without this.

# Windows
Copy-Item .env.example .env
# macOS / Linux
cp .env.example .env

4. Install the frontend dependencies

cd ../frontend
npm install

Run the app

Use two terminals and keep both running.

Terminal 1 · Backend 
cd backend
# activate .venv first
python -m uvicorn app.main:app --reload

API: http://127.0.0.1:8000
Health: /api/v1/health
Swagger docs: /docs

The SQLite database is created automatically in backend/var/.

Terminal 2 · Frontend 
cd frontend
npm run dev

Open http://localhost:3000.

The frontend forwards /api/v1/* to the backend on port 8000. For a different backend, set LABORLINK_API_URL before npm run dev.

Checks to run before every PR

# backend (from backend/, venv active)
python -m pytest
python -m ruff check .

# frontend (from frontend/)
npm run typecheck
npm run lint

To test the whole flow in the browser, follow “Try the full demo” in the README. Use one tab as the employer and another as the worker.

Want a clean database? Stop the backend and delete backend/var/laborlink.db; it’s recreated on the next start. Never commit that file.

Branch & pull request workflow

  1. Start from the latest main 
    git checkout main
git pull origin main
  2. Create your feature branch 
    git checkout -b feature/worker-ratings
    Use a short, descriptive name. See naming.
  3. Make your changes and commit often 
    git status
git add backend/app/services/ratings.py docs/CHANGELOG.md
git commit -m "Add worker ratings after job completion"
    Add specific files rather than git add ., so you don’t commit stray files. Write messages in the imperative (“Add…”, “Fix…”).
  4. Run the checkspytest, ruff, typecheck and lint must all pass (see above). If you touched the UI, test it in the browser.
  5. Push your branch 
    git push -u origin feature/worker-ratings
  6. Open a pull request into mainOn GitHub, click Compare & pull request, set the base to main, fill in the template below, and request a review from Ravish. Or use the GitHub CLI: 
    gh pr create --base main --title "Add worker ratings" --body-file pr.md
  7. Respond to reviewPush more commits to the same branch; the PR updates automatically. Don’t open a new PR for fixes.
  8. Ravish mergesOnce it’s approved, Ravish merges the PR into main. Then clean up: 
    git checkout main
git pull origin main
git branch -d feature/worker-ratings

Before you open a PR

Code

  • Follows the existing style in the files you touched
  • Error responses use the existing {"error": {...}} envelope
  • Frontend shows real API data; no hardcoded fake content

Tests

  • New backend behaviour has pytest tests
  • All existing tests still pass
  • The UI was checked in the browser at phone size

Docs

  • docs/CHANGELOG.md entry with your name and the date
  • docs/API.md updated for any endpoint change
  • docs/EXECUTION_GUIDE.md updated for new setup steps or environment variables

Safety

  • No keys, .env or personal data
  • No backend/var/, .next/ or node_modules/
  • New dependencies are added to requirements.txt or package.json and mentioned in the PR

Keeping your branch up to date

If main moves on while you’re working, bring those changes into your branch before asking for a review.

git checkout main
git pull origin main
git checkout feature/worker-ratings
git merge main
# fix any conflicts, then:
git add <fixed files>
git commit
git push

If you’re unsure about a conflict, ask in the team chat before forcing anything. Never use git push --force on a branch someone else is also working on, and never on main.

Troubleshooting

ProblemFix
The app says it can’t reach the serverStart the backend first (terminal 1), and check http://127.0.0.1:8000/api/v1/health.
Port 8000 or 3000 is already in useStop the other process, or run python -m uvicorn app.main:app --reload --port 8010 and start the frontend with LABORLINK_API_URL=http://127.0.0.1:8010. For the frontend: npm run dev -- -p 3005.
ModuleNotFoundError in the backendThe venv isn’t active, or the requirements aren’t installed. Activate .venv and reinstall.
The map or route doesn’t loadCheck your internet connection. Map tiles and road routes are fetched online.
Voice input is missingUse Chrome or Edge.
The worker’s location isn’t sharedAllow location in the browser, or use “Run a demo trip instead” on the trip screen.
Accidentally committed to main locallyDon’t push. Run git branch feature/my-work, then git reset --hard origin/main on main, and continue on the new branch. Ask if unsure.
